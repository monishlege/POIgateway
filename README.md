# Proof-of-Intent Gateway

This project provides a FastAPI gateway that checks a proposed state transition against a policy edge list and verifies a Groth16 proof with SnarkJS before issuing an outbound HTTP request.

## Security properties and limitations

The circuit proves only that `Poseidon(currentStateHash, actionId, salt)` equals `nextStateHash`. It does not expose `actionId` or `salt`, and the gateway checks that the two public hashes form an edge in the configured policy DAG. In the requested circuit interface, neither the HTTP target nor the request body is a public input. Consequently, the proof does **not** prove that the body or destination expresses the same intent as the hidden `actionId`. Do not treat this design alone as authorization for arbitrary high-impact operations. Production deployments must additionally bind tool identity and canonical request semantics to policy decisions (for example, with a circuit that commits to the canonical request digest and constrains a public action identifier) and authenticate callers at a trusted ingress.

This gateway requires `POI_ALLOWED_HOSTS` and permits HTTPS requests only to exact listed hostnames. It does not follow redirects, uses no ambient proxy settings, and does not permit caller-selected HTTP methods: the forwarded operation is POST. Deploy behind authenticated TLS ingress, restrict egress at the network layer, rotate credentials, and set service-level request and response size limits. The policy DAG is loaded at startup; restart the service after changing it. The local Powers of Tau and zkey contributions generated by the script are not a production trusted setup. For production, use an audited circuit, independently controlled multi-party ceremony, and a verified key/artifact distribution process.

## Prerequisites

- Python 3.10 or newer
- Node.js and npm
- Circom 2.1.6 or newer
- OpenSSL
- A `snarkjs` executable on `PATH` at runtime. The build script installs the npm package locally; either expose `node_modules/.bin/snarkjs` on `PATH` when launching Uvicorn or set `SNARKJS_BIN` to its executable path.

## Build the circuit

From this directory, run:

```bash
chmod +x scripts/build_circuits.sh
./scripts/build_circuits.sh
```

The script compiles the circuit, creates local Powers of Tau and Groth16 setup artifacts, and exports `circuits/build/verification_key.json`. `POI_PTAU_POWER` controls the Powers of Tau size (default `14`, accepted range `12` through `28`). Keep generated proving keys private and distribute the verification key through a trusted deployment process. Do not use the locally generated setup for production authorization.

## Configure the policy

Configure `proxy/policy_dag.json` with the actual policy transitions before deployment. Each entry in `edges` must be an object with decimal-string `currentStateHash` and `nextStateHash` fields; both must be canonical BN254 scalar-field values in `[0, 21888242871839275222246405745257275088548364400416034343698204186575808495617)`. The checked-in graph is intentionally empty, so no transition is authorized until operators install the real policy edges. Self-edges and cycles are rejected at startup.

## Install and run

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export POI_ALLOWED_HOSTS="api.example.com,webhooks.example.net"
export SNARKJS_BIN="$PWD/node_modules/.bin/snarkjs"
uvicorn proxy.main:app --host 127.0.0.1 --port 8000
```

On Windows, activate the environment with `.venv\\Scripts\\Activate.ps1`; set the environment variables with PowerShell's `$env:POI_ALLOWED_HOSTS` and `$env:SNARKJS_BIN` syntax. Place the gateway behind your authenticated ingress and avoid exposing it directly to the public internet.

The API's OpenAPI metadata is served at `/openapi.json`; interactive documentation is at `/docs`. The legal documents are available at `/terms` and `/privacy`. Before public deployment, set `POI_SUPPORT_EMAIL` to a monitored address. The default address uses the reserved `.example` domain and is not deliverable.

Optional environment variables:

- `POI_POLICY_DAG`: policy DAG file path (defaults to `proxy/policy_dag.json`)
- `POI_VERIFICATION_KEY`: verification key path (defaults to `circuits/build/verification_key.json`)
- `POI_ALLOWED_HOSTS`: comma-separated exact HTTPS hostnames; required for forwarding
- `POI_MAX_BODY_BYTES`: maximum incoming request size (default `2097152`)
- `POI_MAX_UPSTREAM_RESPONSE_BYTES`: maximum buffered upstream response size (default `16777216`)
- `POI_UPSTREAM_TIMEOUT_SECONDS`: outbound request timeout (default `30`)
- `POI_VERIFY_TIMEOUT_SECONDS`: SnarkJS verification timeout (default `15`)
- `SNARKJS_BIN`: SnarkJS executable name or path (default `snarkjs`)
- `POI_SUPPORT_EMAIL`: support email published in OpenAPI metadata (default is a non-deliverable reserved address)

## Execute a tool request

`POST /v1/proxy/execute` accepts a JSON object with `target_url`, optional `headers`, `body`, `currentStateHash`, `proposedNextStateHash`, and a SnarkJS Groth16 `proof` object. The proof's public signal order must be `[currentStateHash, nextStateHash]`, matching the circuit declaration. The gateway checks the DAG edge and proof before forwarding the request as an HTTP POST. On successful verification, the response contains the actual upstream `status_code`, response `headers`, and UTF-8-decoded response `body`; an invalid DAG edge or proof returns `403` with `Goal Drift Detected`.

The request's target hostname must exactly match an entry in `POI_ALLOWED_HOSTS`. Do not forward user-controlled secrets in headers to untrusted endpoints. Upstream responses are currently returned as UTF-8 text; binary response handling belongs in a deployment-specific API contract.

## Operational notes

Run multiple gateway workers only after sizing CPU for concurrent SnarkJS subprocesses. Apply OS/container CPU, memory, process-count, and network egress limits. Keep circuit source, compiler versions, R1CS, zkey, and verification key under reproducible artifact control, and verify hashes/signatures during deployment. Keep proving material out of this service; it only verifies proofs.
